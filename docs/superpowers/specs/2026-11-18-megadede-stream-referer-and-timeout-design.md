# Design: Megadede Stream Hoster Referer and Proxy Timeout

**Date:** 2026-11-18  
**Topic:** megadede-stream-referer-and-timeout  
**Status:** Proposed  

---

## 1. Context and Problem Statement

When users watch movies or series from the **Megadede** provider and pause or leave, the item is persisted in `continueWatching` (via PocketBase/LocalStorage). Upon resuming playback from "Continuar viendo" (or playing titles that resolve to Vidhide / Streamwish), the stream often fails or times out when requesting:

```
https://lisstv.isaacdev.site/api/video/m3u8?url=https%3A%2F%2FVyY3AyGtEHNQnhdR.acek-cdn.com%2F...&referer=https%3A%2F%2Fmegadede.mobi%2F
```

### Root Causes
1. **Mismatched Referer:** In `strategies/megadede/get-url.operation.ts`, the referer sent to `/api/video/m3u8` is hardcoded to `https://megadede.mobi/`. However, the underlying stream host (e.g. `acek-cdn.com` used by Vidhide / Morencius / Streamwish) enforces anti-hotlinking protections and intermittent rate-limits when the referer is not the embed host domain (`https://morencius.com/`, `https://vidhidepro.com/`, `https://streamwish.to/`).
2. **Infinite Connection Hangs in `/api/video/m3u8`:** The native `fetch(url, { headers })` in `app/api/video/m3u8/route.ts` lacks a connection timeout. When upstream CDN edges drop SYN packets or delay headers for unrecognized referers or datacenter IPs, the request hangs until the browser or proxy gateway aborts (504/timeout).
3. **IP-Bound Segment Tokens:** Stream tokens generated by pirate embed hosters (`?t=...&s=...&srv=...`) are cryptographically bound to the IP that requested the embed (the Next.js server). Bypassing the proxy for segments (`directSegments: true`) causes residential client IPs to receive 403 Forbidden. Therefore, segment proxying must remain active (`directSegments: false`), but must forward the legitimate hoster referer.

---

## 2. Goals and Non-Goals

### Goals
- Extract and attach the legitimate embed hoster domain (e.g., `https://morencius.com/`, `https://vidhidepro.com/`, `https://streamwish.to/`, `https://voe.sx/`) as the `referer` for both primary and secondary (`fallbackUrl`) streams in `megadede/get-url.operation.ts`.
- Ensure all segment requests continue to be safely proxied through `/api/video/m3u8` with `directSegments: false` to preserve IP-binding validity for upstream tokens.
- Add an explicit connection timeout (`AbortSignal.timeout(8000)`) to the manifest `fetch` in `app/api/video/m3u8/route.ts` so dropped upstream requests trigger immediate fallback instead of hanging the client.
- Operate reliably without requiring external residential proxy services (`USE_PROXY=false`).

### Non-Goals
- Changing the underlying Megadede AES decryption or HTML scraping structure.
- Modifying how `useMovie` or `continueWatching` tracks `currentTime` and `startTime`.
- Enabling client-side direct segment fetching (`directSegments: true`) for Megadede.

---

## 3. Approaches Considered

### Approach A: Dynamic Embed Hoster Referer + Proxy Timeout + Proxied Segments (Chosen)
- In `strategies/megadede/get-url.operation.ts`, store `{ m3u8Url, hosterReferer }` for each decrypted embed candidate.
- Derive `hosterReferer` from `new URL(decryptedUrl).origin + "/"`.
- Pass `referer=${encodeURIComponent(hosterReferer)}` and `directSegments: false` into the proxy URL.
- Add `AbortSignal.timeout(8000)` to manifest fetching in `/api/video/m3u8/route.ts`.
- **Trade-off:** Minimal code changes, robust architectural consistency with `seriesmetro`, preserves token IP-binding, and resolves CDN hotlinking rejections.

### Approach B: Direct Segment Fetching in Browser (`directSegments: true`)
- Route master manifest through server, but have the client browser fetch segments directly from `acek-cdn.com`.
- **Rejected:** Upstream tokens (`t=...`) are cryptographically signed with the requesting IP. If the server extracts the embed, the token is tied to the server IP; client browsers get 403 Forbidden.

### Approach C: External Residential Proxy (`USE_PROXY=true`)
- Route all traffic through paid proxy tunnels.
- **Rejected:** Explicitly rejected by user; adds cost, latency, and unnecessary complexity.

## 4. Detailed Design

### 4.1 Megadede GetUrl Operation (`strategies/megadede/get-url.operation.ts`)
1. Update embed processing loop to retain the hoster referer:
   ```ts
   interface ResolvedStream {
     m3u8Url: string;
     hosterReferer: string;
   }
   ```
2. For each decrypted embed URL:
   - Extract `hosterReferer = new URL(decryptedUrl).origin + "/"` (e.g. `https://morencius.com/` or `https://vidhidepro.com/` or `https://streamwish.to/` or `https://voe.sx/`).
   - Run the respective extractor.
   - If an `.m3u8` is found, push `{ m3u8Url, hosterReferer }`.
3. Construct the response using the hoster referer:
   ```ts
   const primary = resolvedStreams[0];
   const secondary = resolvedStreams[1];

   return {
     url: `/api/video/m3u8?url=${encodeURIComponent(primary.m3u8Url)}&referer=${encodeURIComponent(primary.hosterReferer)}`,
     fallbackUrl: secondary
       ? `/api/video/m3u8?url=${encodeURIComponent(secondary.m3u8Url)}&referer=${encodeURIComponent(secondary.hosterReferer)}`
       : undefined,
     directSegments: false,
     headers: {
       Referer: primary.hosterReferer,
     },
   };
   ```

### 4.2 Manifest Fetch Timeout (`app/api/video/m3u8/route.ts`)
Add a safety timeout to native `fetch`:
```ts
const fetchRes = await fetch(url, {
  headers: fetchHeaders,
  signal: AbortSignal.timeout(8000),
});
```
If the upstream CDN edge drops packets or times out, `fetch` aborts after 8 seconds instead of hanging for minutes, allowing graceful fallback or clean status response.
